MODULE QUICK REFERENCE
================================================================================

1. DynamoDB (modules/dynamodb/)
   Purpose: Single-table compliance data storage
   Key Features:
   - Partition Key (PK) + Sort Key (SK) design
   - Two GSIs: ByFamily, BySeverity
   - DynamoDB Streams for drift detection
   - Point-in-time recovery
   - TTL for auto-cleanup
   - KMS encryption at rest
   - On-demand billing

2. Storage (modules/storage/)
   Purpose: S3 evidence artifact storage
   Key Features:
   - Versioning enabled
   - KMS encryption
   - 7-year intelligent tiering lifecycle
   - Bucket logging
   - SSL/TLS enforcement
   - Public access blocked

3. Lambda (modules/lambda/)
   Purpose: Reusable Lambda function module
   Key Features:
   - Least-privilege IAM role
   - CloudWatch logs (14-day retention)
   - X-Ray tracing
   - VPC support
   - Layer support
   - Dead letter queue
   - ARM64 (Graviton) architecture

4. EventBridge (modules/eventbridge/)
   Purpose: Event-driven compliance collection
   Key Features:
   - Scheduled rule (every 6 hours)
   - Config change detection rule
   - Input transformation
   - Dead letter queue
   - Lambda permissions

5. Cognito (modules/cognito/)
   Purpose: User authentication & authorization
   Key Features:
   - User Pool with security policies
   - OAuth2/OIDC support
   - MFA optional (TOTP)
   - Email verification required
   - Resource scopes (read, write, admin)
   - Hosted UI for login

6. API Gateway (modules/api_gateway/)
   Purpose: REST API with Cognito authorization
   Key Features:
   - Cognito OAuth2 authorizer
   - 5 resources: /controls, /posture, /reports, /scans, /drift
   - Lambda proxy integration
   - CORS configuration
   - CloudWatch logging
   - Throttling (5000 burst, 2000 req/sec)
   - v1 stage deployment

7. Monitoring (modules/monitoring/)
   Purpose: CloudWatch monitoring & alarms
   Key Features:
   - Multi-metric dashboard
   - 4 operational alarms
   - SNS email notifications
   - KMS encryption for SNS
   - Access logging

================================================================================
DEPLOYMENT WORKFLOW
================================================================================

1. Prepare Backend
   $ aws s3 mb s3://compliance-collector-terraform-state-{ACCOUNT}
   $ aws dynamodb create-table --table-name terraform-state-lock ...

2. Initialize
   $ cd environments/dev
   $ terraform init

3. Validate
   $ terraform validate
   $ terraform plan

4. Apply
   $ terraform apply -var-file=terraform.tfvars

5. Capture Outputs
   $ terraform output
   $ export API_ENDPOINT=$(terraform output -raw api_endpoint_url)

6. Deploy Lambda
   $ zip -r src/dist/compliance-collector.zip src/handlers/*
   $ (update terraform.tfvars with ZIP path and re-apply)

7. Test
   $ curl -H "Authorization: Bearer $TOKEN" $API_ENDPOINT/posture
